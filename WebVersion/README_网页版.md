# 雨蚀：第九病区 · 网页版

本目录包含独立 Godot 网页工程与可以直接部署的静态网站。桌面版工程、资源、启动脚本和存档未被改动。

## 开始游戏

双击 **Launch_Web.cmd**，浏览器打开 **http://127.0.0.1:9089/**。点击「进入雨夜」加载，再选择「进入疗养院」或「继续调查」。本机启动服务使用已安装的 Python 3，浏览器运行游戏无需 Godot。服务只监听本机回环地址。退出浏览器后，可双击 `Stop_Web.cmd` 停止服务。

推荐使用最新版桌面 Chrome 或 Edge，开启硬件加速。WebGL 2、WebAssembly、键盘和鼠标为必需；首次加载约 42 MiB（启用 gzip 时）。不要直接双击 `site/index.html`，浏览器会阻止通过 file:// 读取引擎文件。暂未制作手机触屏操作。

WASD 移动，鼠标观察，Shift 冲刺，Ctrl 蹲伏，E 调查，F 手电，左键射击，右键瞄准，R 换弹，Tab 背包，J 日志与提示，Esc 暂停。网页上方提供全屏、说明、存档备份与导入。进入游戏时工具栏隐藏，暂停后重新显示。

浏览器释放鼠标或切换窗口后会暂停。若浏览器要求新的点击才能锁定鼠标，点击「继续观察」。未锁定鼠标时玩家和敌人不会推进。

## 存档

新游戏、安全区录音机和章节节点保存进度。记录使用 Godot 的 IndexedDB 文件系统，仅属于当前浏览器和当前网址；与桌面版存档分开。保存后稍等片刻再关闭标签页，供浏览器写入完成。

清理网站数据、使用隐私窗口或更换网址可能导致原记录不可用。可使用「备份记录」导出 JSON；导入后选择游戏中的「继续调查」或「从最近记录继续」。导入不会立即改变当前局面。版本 1 存档兼容原有角色 ID、死亡记录和剧情状态。

## 部署网站

将 `site` 的全部内容放到静态服务器目录，入口为 `index.html`。也可以解压 `RAINROT_Web_Deploy.zip` 后直接上传包内文件。部署包为避免重复体积省略 `.gz` 副本，托管服务可以自行启用压缩。适合普通 HTTPS 静态托管，无后端、账户或远程存档依赖。本项目已配置 GitHub Pages 自动部署：推送到 `main` 后，Actions 构建并发布到 https://semibluff888.github.io/rainrot/ 。构建进度见仓库 Actions；网页版内容来自 `WebVersion/project`，桌面版修改需要同步移植。

- `.wasm` 的 Content-Type 应为 `application/wasm`，`.pck` 为 `application/octet-stream`，JS 为 JavaScript。
- `.gz` 是可选预压缩副本。服务器选用它时必须发送正确的 `Content-Encoding: gzip` 和原始 MIME。不会配置时直接使用未压缩原文件，仍可运行。Nginx 可使用 `gzip_static on;`。
- 本版本为单线程，不依赖 SharedArrayBuffer，普通托管无需额外配置 COOP/COEP。音频使用 WebAudio Sample 模式。
- 更新时一起替换 `game.js`、`game.wasm`、`game.pck`、`build-config.js` 和网页文件，避免旧缓存混用。推荐对入口和配置使用 `Cache-Control: no-cache`。
- 使用子目录部署时保留所有文件的相对路径。某些平台对单文件大小有限制，应先检查其额度。

## 工程与构建

- `project/`：可用 Godot 4.7.1 直接编辑的网页工程。
- `site/`：完整可部署结果。
- `toolchain/`：官方单线程网页导出模板及来源校验。
- `Build_Web.ps1`：重新导出并更新文件尺寸、gzip 副本与许可文件。
- `tools/serve.py`：只服务 `site` 的本机 HTTP 服务。
- `reports/`：原文件校验、网页构建信息、测试与截图。

在 PowerShell 执行 `./Build_Web.ps1`，或使用 `-Godot` 和 `-Python` 指定安装路径。构建使用本目录内的引擎用户数据目录，避免干扰桌面项目。根目录 `.gdignore` 用于阻止桌面工程导入整个网页副本，请保留它。

## 画面与验证边界

保留完整章节、谜题、手枪、六格背包、两种怪物、强化护士和最终逃生。网页使用 Compatibility / WebGL 2：保留冷暖灯光、雨窗、距离雾、粒子和局部阴影；关闭 Forward+ 专属 SSAO、SSIL、SSR、体积雾和 TAA。高、中、低画质控制分辨率比例、阴影和纹理档位。画布内部像素按比例限制在 1920×1080 内，仍铺满窗口；低、中、高档分别保留 0、3、4 盏投影灯，中高档保留手电阴影。静态盒体按空间和材质批量绘制，移动物件保持独立。

浏览器性能受宿主窗口、显卡驱动、页面分辨率和硬件加速状态影响，不承诺在所有设备上 60fps。完整的本次测试结果见 `reports/WEB_QA.md`。验证页面可在网址后追加 `?qa=integration`、`?qa=enemies`、`?qa=walkthrough` 或 `?qa=pacifist`，点击开始后自动运行，结果显示于页面底部。测试使用单独的测试存档，不覆盖玩家记录。`?qa=manual` 仅显示诊断信息，使用正常玩家存档。

素材与修改署名见 `project/ASSET_LICENSES.md` 与网页的「制作与素材署名」。


## 本轮性能优化与诊断

2026-09-08 的改动与验证见 [性能报告](reports/performance/WEB_PERFORMANCE.md)。正常游玩保持原有操作和存档；高分屏减少不必要的渲染像素，次要灯光保留照明但减少阴影，尘埃更新限为 20Hz。

追加 `?qa=benchmark&quality=1` 可运行真实时间性能采样，quality 为 0 / 1 / 2，默认中画质。四个场景各预热 5 秒、采样 30 秒、重复三次，共约 7 分钟。保持网页在前台，不改变窗口大小；结果在页面底部，包含 P95、慢帧数、画布尺寸与首次启动耗时。测试使用独立测试存档，不保存临时画质选择。失焦、后台或改变尺寸会将该次结果标为无效。

从项目根目录运行 `./WebVersion/Test_Web.ps1 -Rendered` 执行功能、网页外壳和画质回归。需要 Godot 4.7.1 及 Node.js，可用 `-Godot` / `-Node` 指定路径；实际渲染器用于检查尘埃实例变换。重新导出仍使用 `Build_Web.ps1`。

本轮已有原生 Compatibility 对照数据，Chrome/Edge 的实际性能及全屏鼠标验收因浏览器控制连接不可用而待验证，尚未将「浏览器 P95 降低 20%」标为达成。
