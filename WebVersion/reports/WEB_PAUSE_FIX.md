# 网页暂停恢复修复 · 2026-09-08

## 问题与改动

旧流程在 Godot 关闭暂停菜单时请求鼠标捕获，网页点击处理又会请求一次。浏览器的 Pointer Lock 是异步的，旧的「点击画面继续」还在请求完成前发送 resume。ESC 的键盘事件和 pointerlockchange 解锁事件也可能以不同顺序到达，导致刚打开的暂停菜单又被当作普通菜单关闭。由此出现菜单关闭但输入仍被冻结、需要重复点击的问题。

- 暂停菜单的「继续调查」由位于原按钮位置的 HTML 按钮处理真实用户点击；根据 1920×1080 的布局与留黑边比例对齐，鼠标事件不进入游戏射击逻辑。
- 每次只允许一个待处理的锁定请求。菜单在等待期间保留，按钮显示「正在继续…」。
- 仅在 pointerlockchange 确认锁定的是本游戏 canvas 后，先通知引擎锁定成功，再恢复游戏。引擎同时检查锁定状态、页面可见性和当前是否仍是暂停菜单。
- 拒绝、同步异常和旧版无 Promise 的 pointerlockerror 都恢复按钮并显示可重试提示；不自动循环申请、不绕过浏览器的 ESC 后限制。
- 页面失焦、后台或切换到其他菜单时取消待恢复操作；迟到的锁定不得把游戏从其他菜单拉回。
- 网页 ESC 的重复/双重通知不会再次关闭暂停菜单。继续游玩使用「继续调查」；原生版 ESC 行为保持原样。
- Godot 普通网页菜单关闭不再独立抢先发起捕获；尚未捕获时由网页「点击画面继续观察」安全恢复。自动 QA 保持原有输入方式。

## 验证

执行 `./WebVersion/Test_Web.ps1 -Rendered`：

- Node 网页外壳检查：13 项，含单次点击、20 次连续暂停/恢复、拒绝后重试、旧版 error 事件、同步异常、失焦/换菜单后迟到的结果、其他元素的锁定、缩放定位和自动 QA 隔离。
- 引擎集成：55 项；怪物：52 项；常规/零弹药通关。
- 引擎画质与恢复桥检查：34 项，新增未锁定不可恢复、确认后恢复、后台拒绝、保留其他菜单以及20次循环。

Chrome 控制连接连续两次返回 `unsupported Codex auth method: apikey`，因此上述自动事件测试与原生引擎回归不等同于独立 Chrome/Edge 的实鼠标验收；尚未声称真实浏览器已验证一次点击恢复。

手工验收：打开网页版进入游戏，ESC 暂停后点「继续调查」，确认只需一次正常点击、菜单在成功捕获后关闭、恢复点击不触发射击；连续重复20次；再测试切出窗口、浏览器拒绝锁定后重试，以及窗口/全屏缩放后按钮位置。若浏览器刚响应 ESC 暂时拒绝捕获，应看到明确提示，游戏和敌人继续保持暂停。
