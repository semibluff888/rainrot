# 网页版验证记录 · 2026-09-07

测试使用本机 Godot 4.7.1、单线程 WebAssembly / WebGL 2，以及内嵌 Chromium 浏览器。桌面原工程未被启动或重写。

| 检查 | 结果与证据 |
| --- | --- |
| 桌面工程隔离 | 298 个运行输入 SHA256 全部一致，变更 0。见 `desktop_integrity.json`、`desktop_baseline.json`。 |
| 网页资源服务 | HTML、WASM、PCK、脚本、两个音频 worklet 与署名文件均返回 200；WASM MIME 和 gzip 正确。见 `http_checks.json`。 |
| 浏览器集成回归 | 55 / 55。覆盖谜题顺序、背包满、重复拾取、导航、楼梯、保存恢复、重试、实际命中和零弹药出口。见 `browser_integration.json`。 |
| 独立工程最终回归 | 优化静态绘制后，55 / 55。见 `final_compat_test.log`。 |

| 浏览器常规通关 | 成功。4 次射击，结局生命 100，模拟活动时间 130.8 秒。真实角色移动、交互射线和谜题按钮；没有中途传送或关闭敌人。见 `browser_walkthrough.json`。 |
| 浏览器零弹药通关 | 成功。0 次射击，结局生命 76，模拟活动时间 97.2 秒；追逐者穿过楼梯到达出口。见 `browser_pacifist.json`。 |

零弹药初次自动验证在停尸间直线折返时被护士堵住并死亡，原始失败记录保留在 `browser_pacifist_attempt1.json`。随后仅调整自动玩家路线：在前半章使用正常冲刺，并从解剖台南侧绕行；未修改敌人的速度、伤害、生命、攻击窗口或游戏碰撞。该路线先通过引擎测试，再通过浏览器测试。

网页版按材质和空间批量绘制 859 个静态盒体。原有可编辑节点和物理碰撞保留；门、拾取物、角色与可交互道具保持独立。角色纹理为 1024 / 512 px，导入压缩质量 0.88；初始主要资源启用 gzip 时约 41.8 MiB。

两次浏览器通关采样 FPS 中位数为 65.5 和 68.5，存在明显短时低帧。见 `browser_performance.json`。采样混合了内嵌窗口尺寸变化、首次着色器编译与自动测试的固定模拟步长，不能当作固定 1080p 高画质稳定 60fps 的验收。网页高画质、不同品牌显卡以及独立 Firefox / Safari 未全面测试。

当前内嵌浏览器自动化未能确认 Pointer Lock 成功捕获，因此没有把鼠标连续观察、独立浏览器全屏、存档文件下载或主观声音听感标为实测通过。建议使用 `Launch_Web.cmd` 在独立 Chrome / Edge 中游玩；代码已提供用户点击后启动、重新捕获、焦点丢失暂停和未捕获时停止玩家/敌人的保护。音频 worklet 和网页 Sample 播放未报告加载错误，但仍应在目标浏览器上试听。

上述 97 / 131 秒是知道答案的自动路线计时，不代表首次探索时长。此移植没有重新验证最初设计的 20—30 分钟章节时长。
